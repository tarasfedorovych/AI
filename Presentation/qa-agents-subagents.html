Concepts · AI agents02

What is an AI agent?

THE 1-SENTENCE DEFINITION

A language model that can use tools and runs in a continuous loop until it finishes a job.

Everything else — planning, memory, tool use — is implementation detail on top of this.
DEMYSTIFYING THE HYPE
No magical reasoning brain. No secret sauce inside the model that "decides" to act. Under the hood it follows a practical, structured process — predict, act, observe, repeat.
If you can name the loop, you can debug it — that's the point of this deck.

Not magic — a mechanism you can inspect and design

Concepts · AI agents03

Chatbot vs. AI agent

Two additions turn a responder into a doer.

STANDARD CHATBOTS / PLAIN LLMS
Generate text in a single turn, then stop. Cannot check email, search the web, book actions, or update a database.
AI AGENTS
Formed by adding two capabilities to an LLM:
Tool calling — the ability to take real-world actions. The loop — operating step-by-step toward a goal, instead of stopping after one reply.
LLM
+
tool calling
+
the loop
=
AI agent
Concepts · AI agents04

Under-the-hood building blocks

The Brain (LLM)
Predicts the next token from training. No hands, no persistent memory, no capabilities of its own.
LLM (Model)
→ a large language model trained to predict the next token — nothing more on its own
The Hands (tools & harness)
The model outputs structured text naming a tool; the surrounding harness executes it for real and returns the result.
HARNESS (Runtime)
→ software that orchestrates the model: sends prompts, gets results, executes tool calls
Working Memory (context)
Holds instructions, history, tool calls & results. Limited even at 1M tokens, so it must be curated.
CONTEXT WINDOW
→ everything the model sees this call: instructions, history, tool calls & results
Long-Term Memory (RAG)
Facts embedded and stored in a vector database; RAG retrieves only what's relevant into context.
RAG (Retrieval)
→ embeds facts into a vector database, then retrieves only what's relevant into context
The Agentic Loop
Think, act, observe, repeat — until the goal is achieved or the agent gives up.
THE LOOP
→ think, act, observe, repeat — until the goal is met or the agent stops
SYSTEM PROMPT
Sets behavior and rules for the whole session
USER MESSAGES
The inputs — instructions, questions, tool results fed back in
ASSISTANT MESSAGES
The model's own outputs — replies and tool calls

Five parts, one mechanism — a model, a harness, and memory it doesn't have on its own

Two required fields — everything else, Claude Code will infer or inherit

Hands-on · Playwright Skill08

Golden rules, in the generated code

GOLDEN RULES · EVERY GUIDE ASSUMES THESE
1  getByRole() over CSS/XPath — survives markup changes 2  Never page.waitForTimeout() — assert or waitForURL() instead 3  Web-first assertions that auto-retry 4  Isolate every test — no shared state 5  baseURL in config — no hardcoded URLs 6  Mock external services only, never your own app
NAIVE
page.click(
  'div.button-class');
page.fill(
  'input[name="email"]',
  'user@test.com');
WITH THE SKILL LOADED
page.getByRole('button',
  { name: 'Submit' })
  .click();
page.getByLabel('Email')
  .fill('user@test.com');
Semantic locators survive markup refactors — the naive version breaks the moment a class name changes.
